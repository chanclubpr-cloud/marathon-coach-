# คู่มืออัปเกรดแบบไม่กระทบข้อมูลเดิม (ต.ค. 2569)

## ข้อมูลเดิมปลอดภัยไหม

| สิ่งที่แก้ | ผลต่อข้อมูลที่ซ้อมมาแล้ว |
|---|---|
| สูตร Zone | **ไม่แก้ข้อมูลในฐาน** — แอปคำนวณ Zone ใหม่จากผลทดสอบดิบ (ระยะ 3 นาที/12 นาที) ที่เก็บไว้แล้ว ค่าที่เคยแสดงผิด (เช่น 326:26) จะแสดงถูกเองทันที |
| การเดาประเภท Session | มีผลเฉพาะตอนพิมพ์แผนใหม่ ประวัติเดิมคงประเภทเดิม (ถ้าอยากแก้ย้อนหลัง แก้รายวันในหน้า "บันทึก" ได้) |
| เพิ่มประเภท Moderate | เพิ่มตัวเลือก ไม่กระทบของเดิม |
| AI ย้ายไป Edge Function | ไม่เกี่ยวกับข้อมูล — แต่ต้อง deploy function **ก่อน** นำโค้ดขึ้นเว็บจริง (ขั้น 3) |
| สิทธิ์ฐานข้อมูล (RLS) | ไม่ลบข้อมูล; ถ้ามีแถวที่ไม่ผูกกับบัญชี login แถวนั้นจะมองไม่เห็น → สคริปต์มีขั้นตรวจก่อน |
| เพิ่มคอลัมน์/ตาราง zones | ใช้ `if not exists` — มีอยู่แล้วจะข้าม |

> โค้ดทั้งหมดอยู่บน branch `ccr-b1c67374-jpc6so` — **เว็บจริงยังไม่เปลี่ยน** จนกว่าจะ merge เข้า `main`

## ขั้นตอน (ทำตามลำดับ)

### ขั้น 1 — สำรองข้อมูล (5 นาที)
Supabase → Table Editor → เปิดทีละตาราง `profiles`, `weeks`, `sessions`, `zones` → **Export → CSV** เก็บไว้

### ขั้น 2 — ฐานข้อมูล
Supabase → SQL Editor → เปิดไฟล์ `supabase/migrations/20261011_safe_upgrade.sql`
1. รัน **ขั้น 0** → ข้อ 0.1 ต้องได้ 0 ทุกแถว, ข้อ 0.3 ต้องเป็น `text` (ถ้าไม่ใช่ หยุดแล้วส่งผลมาให้ผมดู)
2. รัน **ขั้น 1** และ **ขั้น 2**
3. เปิดแอป login แล้วเช็คว่าประวัติครบ (เทียบตัวเลขข้อ 0.2)

### ขั้น 3 — Edge Function (ย้าย AI key ออกจากเว็บ)
```bash
npm i -g supabase            # ครั้งแรกครั้งเดียว
supabase login
supabase link --project-ref <project-ref ของคุณ>
supabase secrets set ANTHROPIC_API_KEY=sk-ant-...
supabase functions deploy coach
```

### ขั้น 4 — นำขึ้นเว็บจริง
1. Merge branch เข้า `main` (เว็บ build ใหม่อัตโนมัติ)
2. ลบตัวแปร `VITE_ANTHROPIC_API_KEY` ออกจาก Vercel/Netlify
3. **สร้าง API key ใหม่** ที่ console.anthropic.com แล้วลบ key เก่า (key เก่าเคยอยู่ในเว็บ ถือว่าหลุดแล้ว) → ตั้งค่าใหม่ด้วย `supabase secrets set`

### ขั้น 5 — ทดสอบ
- หน้า Zone: ค่าเดิมควรแสดงเป็น pace ปกติ (เช่น 7:40 – 6:40)
- หน้าแผน: กด "ตรวจโปรแกรม" → เห็นกล่อง "ตรวจตามกฎ" และผลจาก AI
- หน้า AI: วิเคราะห์ได้ ไม่มี error

## ถ้ามีปัญหา
- AI error 401/404 → function ยังไม่ deploy หรือ secret ยังไม่ตั้ง
- ประวัติหาย → RLS ไม่ตรง user_id: ใช้ส่วน "ย้อนกลับ" ท้ายไฟล์ SQL แล้วแจ้งผม
